## Question (pre-registered)

With the new kernels, does a hot/cold hybrid beat plain Engine A for moe at T=128?

**Rule:**
- A hybrid arm that is <= 0.97 of master in **every** round, and exact, becomes a moe check candidate (route T=128 to it).
- Otherwise T=128 stays plain, and the margin is recorded.

## Method

- **What is timed:** kernel_fn CUDA graphs, which are the judge's timed path. They run on master's own prepared state at T=128.
- **Draws:** `_ea_judge_routings` p10 / p50 / p90 draws, with a new seed per replicate, so 9 distinct draws.
- **Timing:** `_rt_time`, 8 interleaved rounds x 21 rotated reps per draw. There is a 256 MB read flush before each replay, and the empty graph is subtracted. That gives 24 rounds per replicate and 72 in total.
- **Arms:**

| arm | what it runs |
|---|---|
| m | master, forced to the judge's T=128 route `v4cxs:e4` (E5) |
| m2 | the same, a second copy (A/A null) |
| mn | the node's own route, v4cxs dq2 |
| g16s / g16f | H=-16, old wg hot half, serial / fork |
| w{16,8,24}{s,f} | H in {-16, -8, -24}, wh5ds hot (arm 14) + v4cxs E5 cold, serial / fork (W6-M fork stream) |

- **Exactness**, checked at every draw:
  - Every hybrid arm vs the fp32 reference is within the canary bound (<= 2x master's rel-L2; 0.0043 vs master 0.0039).
  - fork == serial bitwise.
  - wh5ds == wg hot bitwise (H=-16).
  - m == mn bitwise.
  - Graph output == eager output bitwise.
  - errx is 0 and whk_err is [0, WG_MAGIC].
  - **Every check passed in all 3 replicates.** The hybrid outputs are not bitwise equal to master's: a different hot GEMM gives a different fp32 summation order. That is the same as the landed T=256 hybrid.

## Verdict (pre-registered rule)

**No arm qualifies, so T=128 stays plain Engine A E5.**

The forked hybrids (w16f, w8f) pass 56/72 rounds and win 7 of 9 draws by 5-15%. They lose on draws with few hot experts: r2 p10 (max 28 routes, one expert above 16) is x1.04, and r2 p50 (max 46) is x0.99-1.00. The worst round is 1.045 (w8f) / 1.039 (w16f).

The route is per T, and kernel_fn is a captured graph, so no host-side branch on the draw is possible.

**Margin:** mean x0.934 (w16f) / x0.935 (w8f), worst x1.039 / x1.045. No check candidate, so hyp.py triage was not run.

**Transfer caveat:**
- These are forked ratios on H100 HBM. They are a judge-shaped model that does not transfer as numbers.
- CLAIMS has the T=128 hybrid race flipping sign node -> judge (H100:229-231).
- On the judge, the earlier wg + v4-cold T=128 hybrid lost x0.94-0.95.

**Reopen if:** a device-side hot-count gate (hybrid only when some local expert has more than about 32 routes, else plain) would make the losing draws plain. That would need a graph-safe in-kernel dispatch, and it was not built.
