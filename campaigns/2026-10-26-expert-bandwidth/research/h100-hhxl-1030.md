## 0. Gate: had hh1-4 already measured XL-style trims?

**No, not as such.** hh3 measured the issue cost of the consume loop (SASS per stage, ncu issue 37-45%) and ported
one trim of the XL kind, D (descriptor hoist: uniform ops per stage 52 -> 32). hh4 tested more independent work per SMSP.
Neither touched the rest of XL's L: the stage index and phase recomputed from `n` each stage, `full0` / `empty0`
rematerialised from `SR_CgaCtaId` (an S2UR every stage, on the path to the full-barrier try_wait), the per-thread smem
addresses rebuilt from `s`, and `dead` tested before the try. So this lane ran.

XL = X + L.
- **X (ldmatrix.x4 B preload) has no counterpart here.** In wg_kernel the B operand goes from smem to the tensor core
  through the wgmma descriptor, so there is no B register load. X was null in Engine A anyway (ea-enc2).
- **L** is what got ported.

## 1. Arms (gen_xl.py: asserted edits on hh4's `gen/hh_wh5ds.cuh`; master's wg text is unchanged since hh4, `_wg_src(True)` sha256 26b3286b)

| arm | what |
|---|---|
| dq0 | master's wg_kernel (canary reference) |
| wh5ds | master's arm 14 (`wg_kernel<G,14>`): x5 + D, SC loop N <= 32, R4 ring N >= 48 |
| **whxl** | wh5ds + L in both loops. Per item the loop carries the full-barrier address (empty = +32), the phase, and the stage byte offset, stepped +1 and wrapped by one select. The per-thread code/scale pointers and the stage-0 descriptor low word are hoisted. The trip count runs down, and `n += KS` happens once. `xl_wait` tries first and reads `dead` only on the slow path. The math is untouched. |
| whxl2 | whxl + the descriptor low word also loop-carried (ptxas re-derived it from the smem base each stage in whxl) |
| co5 / cox / cox2 | wh5ds / whxl / whxl2 with a **consume-only** producer: once the ring is full (n >= STAGES), each slot is re-armed with a plain `mbarrier.arrive` (no expect_tx, no TMA), so the consumers re-read resident smem. This is ea-enc2's `c` mode. Timing only. |

**SASS (cu130, instructions per 128-k stage, w13; w2 the same).** All 7 kernels: 168 regs, 0 spill, 0 stack, no C75xx.

| N | wh5ds | whxl | whxl2 |
|---|---|---|---|
| 16 / 32 (SC loop) | 191 (32 uniform) | 193 (34) | 190 (31) |
| 48-112 (ring) | 206 (31) | 210 (35) | 208 (33) |
| 128 | 209 | 216 | 217 |

- **L does not cut issued instructions here.**
  - The S2UR, the signed `n % 4` / `n / 4` and the `dead` test left the loop.
  - ptxas spent the savings on UR moves around the HGMMA descriptor pair (`UMOV UR18, UR12` + `UMOV UR19, 0x40000040` per
    wgmma).
- Unlike Engine A, where L cut 67 -> 24 issued instructions of bookkeeping per ~600-instruction record, hh3's D had already
  moved this loop's bookkeeping onto the uniform datapath.
- What L still buys is a shorter chain before the try_wait: no S2UR -> ULEA -> ULEA ahead of each stage.

## 2. Measurement

- **Driver:** hh4's `hh_main.cu` with the variant table cut to the 7 arms; banks as in hh3/hh4.
- **Time mode:** routings dec-T256-{a,b,c}, dec-T128-{a,b,c}, jd-T256 and jd-T128, in the sets w13, w2, pair (w13 -> PDL
  w2) and fork-spin. Each process ran 61 reps x 5 interleaved rounds. **3 sequential processes = the 3 replicates.**
  Ratios are paired per round.
- **kstep:** cycles per stage per N, at grids G/2 vs G/4 (`--kdiv 2`), 3 processes x 3 rounds.
- **Exactness:** 48 canary lines (8 routings x w13/w2 x 3 processes). whxl and whxl2 are **bit-identical to dq0 (diff 0) in
  every one**. The co arms differ by construction.

**Hot-half share** of the expert block, from the harness's cold calibration R (cold alone = R x the hot pair; hot =
1 / (1 + R)):
- dec-T256: R 1.011, hot 49.7%;
- dec-T128: R 1.97, hot 33.7%;
- moe jd-T256: R 1.91, hot 34.4%;
- moe jd-T128: moe does not fork at T=128 (Engine A only), so hot 0%.

T = 8..32 has no wg hot half (WG_MIN_TOKENS 128), so the hot half carries weight only at T = 128 / 256.

**Judge scaling:** x0.5. This is the XL moe evidence from the brief: a node consume-only cut of 2-5% showed up as
~1-2.5% per class on the H200. Unscaled numbers are shown too.

## 4. Verdict (pre-registered rule)

**Null. No trimmed wg arm qualifies.**
- Both trimmed arms are bit-exact.
- The best consume-only hot-half cut is 4.4% at a single draw (dec-T128-b, cox, all 3 replicates 0.956-0.957). That is
  2.2% judge-scaled.
- Class means are 2.5% (decode T=256), 3.1% (decode T=128) and 1.9% (moe T=256) unscaled, and 1.0-1.6% judge-scaled.
- No class reaches the 4% bar, judge-scaled or not.
- In normal mode the trims are 0.990-1.012, and dec-T128-b is slower in normal mode. Forked they are 0.991-0.998, so the
  headline is about +0.1-0.3% at most.

**No moe submission change was built.** There is no `campaign/hhxl` branch and no `.worktrees/hhxl`.

**Why it is small:**
- hh3's D had already moved this loop's bookkeeping onto the uniform datapath. L removes no issued instructions; ptxas
  re-spends them on descriptor UR moves.
- What remains is the S2UR / ULEA chain ahead of each stage's try_wait. That is ~2-5% of a stage at N48-96 and nothing at
  N >= 112.
- This agrees with hh3/hh4: the N <= 64 stage is a latency chain (dequant + dependent wgmma), not issue-bound. XL's L
  paid in Engine A because Engine A's mma.sync record loop is issue-bound.

**Rider value, if wh's next revision touches the loop anyway:**
- An N-gated whxl (L at N <= 96, wh5ds's loop at N >= 112) is free and bit-exact.
- The node shows +0.5-1% on the hot pair, which is <= ~0.2% headline. It is not worth a check of its own.
