## SASS (cu13.0, ea4x w13 one-tile path; per 32-step record)

Static per-step costs are E5 = 16.4 issued: HMMA 1, HMUL2 4, A4b codes 9 (7 ALU + 2 IMAD), A5b scale 1.5, LSU 0.9.
The code views are exhausted: rgx2 found no 8-op encoding. A zero-op scale is not possible because the fields must sit
at bits 4-10 / 20-26, and 16 fields in 4 words means 8 of them need a shift. Removing the shift would need 2x scale
bytes, which is +11% record bytes. **(c) is rejected.**

The waste the SASS showed was the per-record loop bookkeeping: 67 issued / 33 ALU per record. ptxas rematerialised
every per-record address from threadIdx and redid i % D, q / NK and the consume prologue.

| arm (dq) | regs | body+prologue issued / ALU | loop overhead issued / ALU | per record ~issued / ALU-cyc |
|---|---|---|---|---|
| E4 (3) | 82 | 577 / 270 | ~40 / ~20 | 617 / 580 |
| E5 (4) | 83 | 560 / 282 | ~40 / ~20 | 600 / 604 |
| E4X (11): ldmatrix.x4 B preload | 84 | 563 / 272 | ~40 / ~20 | 603 / 584 |
| E5X (12) | 83 | 546 / 284 | ~40 / ~20 | 586 / 608 |
| E4XL (27): X + trimmed loop | 94 | 542 / 261 | 24 / 9 | 566 / 540 |
| E5XL (28) | 92 | 526 / 273 | 24 / 9 | 550 / 564 |

L works as follows. Addresses are loop-carried and stepped by IMAD (s = +-1), so ptxas cannot rematerialise them. The
wait tries first, a count-down replaces kc / q, and the pass constants are recomputed only at run ends. The A-priori
projection was -6..-9%.

## Verdict (pre-registered rule)

**No arm qualifies.** No arm clears 5% over the master-routed arm on both kernels of any class. The only pass is
T = 256 w13 with E5XL (1.049-1.055; w2 reaches 1.039-1.044), and that row is roughly 55% Engine A. So
**no moe check candidate** comes from this lane. If someone wants to stack it later, E5XL / E4XL (loop trim) is a
