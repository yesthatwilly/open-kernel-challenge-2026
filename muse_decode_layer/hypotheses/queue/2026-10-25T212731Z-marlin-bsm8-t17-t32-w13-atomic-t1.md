# marlin-bsm8-t17-t32-w13-atomic-t1

## Change

Two shape-disjoint Marlin call-knob cells on master, stacked because each alone is below the margin; each has its own constant, prepare flag, selector and PATH CHOSEN line, so a row move is attributable to one cell. No new kernel. CELL A (17 <= tokens <= 32, i.e. decode_32 and the T=17..31 tests): use block_size_m 8 instead of _block_size_m(T) = 16, gated on a new constant BSM8_MIN_TOKENS = 17 / BSM8_MAX_TOKENS = 32 (not derived from DL_MAX_TOKENS) and state['bsm8_on']. The same 8 must reach kernel R's align (the bsm argument of _dl_route_launch / dl_route_norm_align; _dl_route_bufs sizes n_blocks from it: capacity 32*8 + 32*7 = 480 slots at T=32) and both moe_wna16_marlin_gemm calls' moe_block_size. R's align at (T=32, bsm 8) has never been self-checked: run master's _dl_align_problems / _dl_self_check at T = 17, 24, 32 with bsm 8 before enabling. Mechanism: at T=32 the soft routing gives ~32 local routes over ~15-20 active experts (1-3 rows each), so bsm 16 pads 13-15 of every 16 rows, and Marlin's per-m-block cost grows with block size (moe next-larger lost 18-28%; decode cap-16 gained 8-15%); decode_16 already runs bsm 8 at T=16. The risk is a hot expert above 8 rows taking 2 blocks and re-streaming its weights (moe marlin-block-m-8-verify16 lost at T=128 for exactly that: 391 vs 341 us), which the zipf routing in the selector exposes. CELL B (tokens == 1, decode_1 both layers): pass use_atomic_add=True on the w13 Marlin call too (master already does it on w2 at T=1 via state['w2_mode']), with the same 'atomic' / 'atomic_zero' mode pair master's w2 cell self-checks with a W2_JUNK-poisoned buffer (here cache1 poisoned before w13); moe's F1 cell measured the w13 call alone 27.20 -> 25.82 us on zipf and 18.43 -> 13.76 us on random routing and went live in moe's toprow combo at 0.949. SELECTOR per cell: master's whole _experts graph (A at T = 17, 24, 32; B at T = 1, R's align path) vs the cell, zipf-skewed and random-local routing, worse-of-two >= 1.02x. Self-check rel-L2 vs an fp32-dequant reference <= max(1.5x master's own error, 1.25e-2) and vs master. Print '[mk] PATH CHOSEN A T=<t>: bsm8 X us vs bsm16 Y us (zipf), ... (random)' and '[mk] PATH CHOSEN B T=1: w13 atomic X vs master Y'. If the fsi stage that covers a cell's T is live, that cell is moot (it times against the incumbent as routed). HARD RULES (every path): CUDA-graph capturable; kernel_fn has no host sync, no timing, no prints, no try/except, no allocation sized by input values (shape/config only), no data-dependent Python control flow and no per-call mutable Python state; gates read config/shape and this state's own prepare() flags only; nothing cached from inputs; NVFP4 weights stay NVFP4 (lossless repack allowed, dequant in registers only), BF16 stays BF16; no child processes.
