## Change

Built on master d5595769 (dense-chain-s3 landed). The host wrapper dl_unpool already dispatches m <= 8 to the same NF=1 instantiation, and the kernel was written as T <= 8 code (stack-route-topk-pdl-unpool-nf1 / boundaries-unpooler-pdl-small-t). Widen piece C to 2 <= T <= SLICED_UNPOOL_MAX_TOKENS (8): verify_1 (T=8) on both layers, plus the batch-8 and batch-1..8 tests that land at T <= 8. kernel_fn: change the piece-C condition 'use_dl and tokens == 1 and dl3 is not None and dl3["u"]' to 'use_dl and dl3 is not None and ((tokens == 1 and dl3["u"]) or (2 <= tokens <= SLICED_UNPOOL_MAX_TOKENS and dl3["u8"]))'. That is config plus a per-state flag only, and T=1 behaves exactly as now. prepare(): (1) extend _dl3_check_u with T in (2, 5, 8), using the same poison fill, rel L2 <= 2e-3 against _unpool_master, the exact-zero columns test, two reps each and the ticket-reset check, on a separate failure list so a T=2..8 miss clears only the new flag. (2) Add a selector, _dl3_select_u8, a copy of _dl3_select_u at T=8 (y [8, 4096]): new kernel vs slice GEMM + F.pad as graph replays behind the 256 MB flush, through _dl3_verdict with DL3_MARGIN 1.02. (3) Set d3["u8"] = (check ok and selector win), default False, in the per-state dl3 dict and in _dl3_ministate / _dl3_flags so the second state carries its own flag. (4) Run one more eager layer check at T=8 (batch 1, q_len 8, both layer types), master vs u8 on, through the existing _dl3_layer_checks comparison (hidden and stream rel L2, ids, cache, finiteness), and add T=8 to the alternating two-state graph replay check. ## Risk

Risk: low. The kernel instantiation, workspace and ticket are the ones T=1 already uses in the judge, and the host dispatch for m <= 8 already exists. New are only the rows 1..7 of the n8 fragment (zero-filled by cp.async src-size 0 for rows >= m) and the split-K reduce over 8 token rows of the ws [SPLIT, 32, 1024] workspace. Both are covered by the T=2/5/8 checks, and a miss clears only u8. The only cost is prepare time (~1 s of checks). The gain is small (~0.2-0.3% headline), so judge it on the verify_1 rows (paired ratio) and the kernel rows, not the headline.
