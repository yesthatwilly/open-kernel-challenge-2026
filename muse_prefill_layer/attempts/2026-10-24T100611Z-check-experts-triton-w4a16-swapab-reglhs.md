## Goal
Stage 2 of the Triton NVFP4 grouped GEMM, built on stage 1 (branch hyp/muse_prefill_layer/experts-triton-w4a16-inkernel-fp4, _moe_nvfp4_gemm_kernel in muse_prefill_layer/submission.py). The one fix: swap A and B so the in-register dequantized weight tile is the LEFT (register-sourced) operand of the tensor-core dot. Stage 1 computes acc[tokens, n] += tl.dot(A[tokens, k], tl.trans(tl.interleave(w_lo*sb, w_hi*sb))): the dequantized bf16 weight is the RIGHT operand, which sm_90 wgmma can only read from shared memory (and at BLOCK_M 16/32 Triton emits mma.sync regardless), so every K step pays interleave + trans + a layout conversion / local_store round trip of 8192 bf16 weight elements through smem, while the MMA sees only 16-32 token rows at turn_1. That per-tile overhead is what the profile shows (2026 us for w13+w2 at turn_1 vs Marlin 730 us; 13.5 ms at first_turn = ~120 TFLOP/s, i.e. no effective wgmma). Stage 2 computes the transpose, acc[n, tokens] += tl.dot(W[n_tile, k_tile], A_t[k_tile, tokens]): (1) Operands. The weight tile is the MMA M side: BLOCK_W = 128 rows of the expert N (wgmma M = 64 per warpgroup); the tokens are the MMA N side (wgmma n = 8..256). The dequantized [128, BLOCK_K] bf16 tile feeds tl.dot as the LHS straight from registers (Triton MMAv3 LHS-in-registers path, the one its mixed-precision upcast matmuls use); only the bf16 activation tile, loaded with tl.load as [BLOCK_K, BLOCK_T] from K-contiguous rows (offs_k[:, None] + (offs_token[None, :] // TOP_K) * K, the master router orientation trick), is pipelined through smem. Load the uint8 code tile and scale tile in their natural blocked layout and do the bit ops there; let Triton hoist the convert to the dot-operand layout onto the uint8 codes (4x fewer bytes than bf16). (2) No interleave or trans: a lossless nibble reorder in prepare(). Within each BLOCK_K = 128 chunk of K, repack the uint8 codes so byte i (0..63) holds k0 + i in the low nibble and k0 + 64 + i in the high nibble (a permutation of the same E2M1 codes; sf and gs untouched; stored as state bank w13/w2 in place of the original packing, same [E, N, K/2] uint8 shape). The low nibbles are then the contiguous k-half [k0, k0+64) and the high nibbles [k0+64, k0+128), and each K step is two dots: acc = tl.dot(w_lo, a_t_lo, acc); acc = tl.dot(w_hi, a_t_hi, acc), with the activation tile loaded as two [64, BLOCK_T] slabs at k0 and k0+64 (pointer offsets only, no reshape/split). Scales: low half sf group k0/16 + i//16, high half k0/16 + 4 + i//16, loaded as [128, 64] gather tiles (L1 hits) as stage 1 does. Keep stage 1 bit-placement E2M1 -> bf16, the 2^119 scale bias (sb multiply per element), and gs[e] * 2^7 once in the epilogue. (3) Token tile from the local rows (~T/32 per expert), so each expert is one m-block at the turn shapes and each weight element is dequantized once per call there: BLOCK_T 64 for T <= 1024 (turn_1, ~24 rows; MMA padding is free since the shape is dequant/memory-bound), 128 for T <= 4096 (turn_4, ~94 rows), 128 above (first_turn, ~512 rows = 4 token tiles per expert); moe_align_block_size pads to BLOCK_T. Order program ids so the token tiles of one (expert, weight tile) run adjacent (token-tile index fastest; drop GROUP_SIZE_M) so the dequantized-from tile is re-read from L2 at first_turn. num_warps 4 (one warpgroup) at BLOCK_T 64, 8 at BLOCK_T 128; BLOCK_K 128; num_stages 3. Fixed configs chosen from T only; no autotune. (4) Epilogue: acc is [BLOCK_W, BLOCK_T]; store (acc * gs) as bf16 through transposed pointers c_ptr + offs_token[None, :] * N + offs_w[:, None], masked by token_mask[None, :]. The -1 (non-local) guard and ZERO_NONLOCAL_W2 zero-store keep their stage 1 semantics in the transposed indexing. Unchanged from stage 1: moe_align_block_size call (with BLOCK_T), silu_and_mul(expert_ids=local_ids), cache13/cache2 buffers, fused_post_expert_norm_weighted_sum(slot_expert_ids=local_ids), everything outside the expert block. prepare(): rewrite _check_expert_gemms for the reordered layout, comparing against nvfp4.dequantize of the ORIGINAL weights on a mid-K tile that spans both nibble halves and all 8 scale groups of one 128-chunk, for every config (this also warm-compiles them). Before the run, compile one BLOCK_T 128 config locally if possible and check the TTGIR for ttng.warp_group_dot with a register LHS (dot_op opIdx = 0, parent = mma v3) rather than a local_alloc memdesc; record the finding in the implementation notes either way.

## What changed, and where
Worktree `.worktrees/muse_prefill_layer/experts-triton-w4a16-swapab-reglhs`, file `muse_prefill_layer/submission.py` only (uncommitted, built on 6a70bfa's stage-1 kernel). Diff: 1 file, +136 / -86.

- `_moe_nvfp4_gemm_kernel` rewritten as swap-AB: `acc[BLOCK_W, BLOCK_T] = tl.dot(w_lo, a_lo, acc); tl.dot(w_hi, a_hi, acc)` per 128-k step. The weight tile ([128, 64] bf16 per half, dequantized in registers) is the LHS. The activation is loaded as two [64, BLOCK_T] slabs, `a_ptr + (offs_token[None, :] // TOP_K) * K + offs_h[:, None]` and the same + 64 (pointer offsets only). The uint8 codes load as [128, 64] in the natural layout, and the bit ops run there. Stage-1 E2M1 to bf16 bit placement, the 2^119 scale bias and `gs * 2^7` in the epilogue are unchanged. No `tl.interleave` / `tl.trans`.
- Scales (reviewer note): one compact [128, 8] e4m3 tile per 128-k step (8 contiguous bytes per row). It is converted to bf16 `* 2^119` once (8 converts per row instead of 128), split into groups 0..3 / 4..7 with `reshape(BW, 2, 4) -> permute(0, 2, 1) -> split`, and each half is broadcast to [128, 64] with `broadcast_to([BW, 4, 16]) -> reshape`. I could not check whether Triton keeps this broadcast in the dot-operand layout or does it through a layout conversion (see TTGIR below). If the turn_1 row barely moves, look here first.
- Epilogue and -1 path are transposed: `c_ptr + offs_token[None, :] * N + offs_w[:, None]`, masked by `token_mask[None, :]`. ZERO_NONLOCAL keeps its stage-1 semantics.
- Configs (`EXPERT_CONFIGS`): T <= 1024 uses BLOCK_T 64 / num_warps 4; above that, BLOCK_T 128 / num_warps 8. Both use BLOCK_W 128, BLOCK_K 128 (`EXPERT_BLOCK_K`, asserted to match the stored nibble order) and num_stages 3. The spec's T <= 4096 and "above" entries were the same config, so they are collapsed into one unbounded entry. Behaviour is identical. `moe_align_block_size` pads to BLOCK_T.
- prepare(): `_reorder_nibbles` builds NEW uint8 [E, N, K/2] tensors for `bank["w13"]` / `bank["w2"]` (reviewer note: weights["w13"/"w2"] are not mutated). Within each 128-chunk, byte i = code(k0+i) | code(k0+64+i) << 4. The repack runs per expert to bound temporaries. Each expert is checked to invert bit-exactly to the original bytes (lossless permutation, untimed). sf/gs are as stored.
- `_check_expert_gemms(bank, weights)` now compares the kernel on the reordered bank against `nvfp4.dequantize` of the ORIGINAL packing. The tile is a mid-K 128-aligned chunk (k0 = K/2 + 128) with CHECK_K = 128 one-hot columns over 128 rows: both nibble halves, all 8 scale groups and every N row through the transposed epilogue. It runs for every config, which also warm-compiles them. The -1 block / past-n_padded checks are kept.
- **Deviation:** the spec says to drop GROUP_SIZE_M and order token tiles fastest. I kept a group swizzle (`GROUP_SIZE_T = 8`) with the token-tile index fastest *within* the group, as stage 1 already had. Token tiles of one (expert, weight tile) still run adjacent, so the weight tile is re-read from L2. Dropping the group entirely would make one wave sweep all ~160 first_turn token tiles at a single weight tile, so the w13 activation (16384 x 8192 bf16 = 256 MiB, larger than L2) would be re-read from DRAM once per weight tile (64x, ~16 GB, ~3.4 ms). At the turn shapes the two orderings read the weights once either way. To follow the spec literally, set GROUP_SIZE_T to a value >= num_pid_t (one group).

## Risks / what could fail
high
High risk. (a) Triton may refuse or silently not use the register-LHS wgmma path for a computed bf16 tile (then it falls back to an smem store of the LHS, still without interleave/trans; the first_turn row tells which). (b) The nibble reorder changes the stored packing: the prepare() check against nvfp4.dequantize of the original weights must cover both halves and the scale-group indexing, or a layout bug fails the tests. (c) Register pressure at num_warps 4 with a [128, 64] bf16 LHS plus a [128, 64] fp32 acc; spills show as a turn_1 time near stage 1. Rules: NVFP4 stays NVFP4 (a lossless code permutation, repacked once in prepare(), as Marlin repacking was), dequant only in registers, no BF16 weight copy, no autotune, no host sync, nothing input-derived cached; configs branch on T only.
